# Glossary

| Term | Meaning |
|---|---|
| **Attack path** | A finding (`NM-PATH-001`) for a workload that is internet-exposed, has an exploitable weakness and holds privileged access or reaches data |
| **CBOM** | Cryptography Bill of Materials (CycloneDX 1.6): where code uses which algorithms |
| **CIEM** | Cloud identity and entitlement management: who can do what across cloud accounts and clusters |
| **CSPM** | Cloud security posture management: configuration checks for cloud accounts |
| **CWPP** | Cloud workload protection: runtime detections on running workloads |
| **EPSS** | Exploit Prediction Scoring System (FIRST): probability that a CVE is exploited in the next 30 days |
| **Fingerprint** | Hash that identifies the same finding across scans and tools |
| **Gate** | The pass / warn / block decision of the policy for a commit, in CI or before a deployment |
| **Inventory** | Normalised configuration of one cloud account or cluster |
| **KEV** | CISA Known Exploited Vulnerabilities catalog |
| **KSPM** | Kubernetes security posture management |
| **MRS** | Myelin Risk Score, 0–100 |
| **OSPS Baseline** | OpenSSF Open Source Project Security Baseline: repository practice controls |
| **Reachability** | Evidence that first-party code imports the vulnerable package |
| **SBOM** | Software Bill of Materials (CycloneDX, SPDX) |
| **SSVC** | CISA Stakeholder-Specific Vulnerability Categorization: Track, Track\*, Attend, Act |
| **Tenant** | One organisation; all of its data is isolated by PostgreSQL row-level security |
| **VEX** | Vulnerability Exploitability eXchange: statements that a product is or is not affected |
