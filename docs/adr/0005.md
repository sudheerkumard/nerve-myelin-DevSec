# ADR 0005 · Read-only cloud collectors and one normalised inventory

**Status:** Accepted

## Context

Cloud posture needs configuration from three clouds and Kubernetes, also at sites without internet access, without giving the platform power over the customer's accounts.

## Options considered

1. Write-capable agents in each account
2. Provider-specific rule engines on raw API responses
3. Read-only collectors that produce one normalised inventory

## Decision

Collectors call only read APIs (Azure Resource Graph, AWS describe/list, Google Cloud Asset Inventory, Kubernetes get/list) with least-privilege credentials from the vault, and produce one inventory shape. Rules run on the inventory only. Provider-native exports and inventories collected elsewhere are accepted for air-gapped sites.

## Consequences

- Rules are tested on labelled inventories without cloud access.
- The platform cannot change cloud resources and never reads data or Kubernetes Secrets.
- A new resource type needs a mapper in the inventory and rules; the catalogue documents what is covered.
